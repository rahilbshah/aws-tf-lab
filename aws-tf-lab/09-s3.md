# 09 – S3 (index / map of content)

Object storage — heavily tested across all four SAA-C03 domains, and the backbone of a dozen other AWS services. Split by course section; each sub-note is self-contained, with its own TL;DR, worked examples and weak spots. Drilling happens in the `aws-saa-trainer` app; these notes are the learning tier.

> [!info] Exam TL;DR — one-paragraph orientation
> **S3 stores objects in buckets.** Bucket names are **globally unique** (precisely: unique across every account and Region within a *partition* — `aws`, `aws-cn`, `aws-us-gov`, `aws-eusc`; "globally unique" is the expected exam answer). The **key** is the object's full path-like name, and a **general purpose bucket** — the normal kind — is a **flat key→object map**, where console "folders" are a display trick over `/`. (The newer **directory buckets** behind S3 Express One Zone are the exception: they have a real hierarchical namespace.)
>
> Two different numbers: **durability** is the chance an object is never lost, **availability** the chance you can read it right now. Every *current* class is **99.999999999% (11 nines) durable** — the exception is the legacy **Reduced Redundancy Storage** at 99.99%, which AWS recommends against — and objects are stored across **≥3 AZs**, except the **One Zone** classes and **S3 on Outposts** (a single on-premises Outpost).
>
> **Storage classes** trade storage price against how often and how fast you need the data: Standard → **Standard-IA** → **One Zone-IA** → Glacier Instant → Glacier Flexible → Deep Archive, cheaper to store as you go right. (**IA** = *Infrequent Access*: cheaper per GB, but you pay a retrieval fee.) **Intelligent-Tiering sits off that ladder** — it is for *unknown* access patterns, charges a per-object monitoring fee and no retrieval fee, and an object that stays hot just stays in its Frequent Access tier. **Lifecycle rules** move and expire objects automatically.
>
> **Versioning** keeps every write as a new version, and a delete *without* a version ID only adds a **delete marker** — a placeholder that hides the object while every older version stays stored and billed. To remove data for real you delete a **specific version id**, which is permanent.
>
> Access is controlled by **IAM policies + bucket policies + Block Public Access**. Objects are **encrypted at rest by default with SSE-S3** (every new upload since 5 Jan 2023); you can instead choose **SSE-KMS**, **DSSE-KMS** or **SSE-C** server-side (SSE = *server-side encryption*, S3 encrypts after the object arrives and the suffix says whose key), or encrypt **client-side** before upload so S3 never sees plaintext or the key. Note **SSE-C has been disabled by default since April 2026** and must be enabled deliberately.
